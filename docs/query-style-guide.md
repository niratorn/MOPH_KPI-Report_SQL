# คู่มือรูปแบบการเขียน Query (Query Style Guide)

เอกสารนี้กำหนดมาตรฐานการเขียนและจัดเก็บ query ในชุมชนนี้
เป้าหมายคือให้ query จากทุกโรงพยาบาลอ่านง่าย ปรับใช้ง่าย และตรวจสอบได้

ก่อนเขียน query ใหม่ ควรอ่าน [docs/hosxp-basics.md](hosxp-basics.md) และ [docs/data-privacy.md](data-privacy.md) ประกอบ

> query ในชุมชนนี้ใช้เพื่อตรวจสอบและเตรียมข้อมูลภายในโรงพยาบาลเท่านั้น ไม่ใช่ค่าทางการ
> ค่าทางการอ้างอิงจากระบบ HDC ของกระทรวง (https://hdcservice.moph.go.th)

## 1. โครงสร้างโฟลเดอร์

query ทุกตัวอยู่ใต้ `queries/` โดยแยกเป็นหมวดและโฟลเดอร์ย่อยของตัวชี้วัด:

```
queries/<หมวด>/<ชื่อ-query-kebab-case>/
    README.md    <- นิยาม, แหล่งอ้างอิง, วิธีใช้, ตัวอย่างผลลัพธ์ (ข้อมูลสมมติ)
    hosxp.sql    <- query สำหรับ HOSxP (MySQL/MariaDB)
```

กติกา:

- ชื่อโฟลเดอร์ใช้ kebab-case ภาษาอังกฤษ เช่น `maternal-anemia`, `preterm-birth`
- ไฟล์ SQL หลักของ HOSxP ชื่อ `hosxp.sql` เสมอ
- ถ้าในอนาคตมี query สำหรับ HIS อื่น ให้ใช้ชื่อไฟล์ตาม HIS นั้น เช่น `jhcis.sql` อยู่ในโฟลเดอร์เดียวกัน
- หนึ่งโฟลเดอร์ = หนึ่งตัวชี้วัด อย่ารวมหลายตัวชี้วัดไว้ในไฟล์เดียว
- ดูหมวดที่มีอยู่แล้วใน [queries/README.md](../queries/README.md) ก่อนตั้งหมวดใหม่

## 2. Header metadata

ทุกไฟล์ `.sql` ต้องขึ้นต้นด้วย header block รูปแบบนี้เท่านั้น
(copy จาก [templates/query-template.sql](../templates/query-template.sql) ได้เลย):

```sql
-- ============================================================
-- ชื่อตัวชี้วัด :
-- หมวด        :
-- HIS         : HOSxP (MySQL/MariaDB)
-- ทดสอบกับรุ่น  : ยังไม่มีการยืนยันจากโรงพยาบาลจริง (รอ community ช่วยทดสอบ)
-- สถานะ       : draft
-- ผู้เขียน      : MOPH KPI SQL Community
-- อัปเดตล่าสุด  : 2026-07-18
-- นิยามอ้างอิง  : (สรุปสั้น + ให้ดู README ในโฟลเดอร์เดียวกัน)
-- สิ่งที่ต้องปรับตามโรงพยาบาล : (list)
-- ข้อจำกัด     : (list สั้น)
-- ============================================================
```

ความหมายของแต่ละ field:

| Field | ความหมาย |
|---|---|
| ชื่อตัวชี้วัด | ชื่อตัวชี้วัดภาษาไทยแบบเต็ม ตรงกับชื่อใน README ของโฟลเดอร์ |
| หมวด | หมวดตาม `queries/` เช่น อนามัยแม่และเด็ก (mch-anc) |
| HIS | ระบบ HIS ที่ query นี้เขียนสำหรับ ปกติคือ HOSxP (MySQL/MariaDB) |
| ทดสอบกับรุ่น | รุ่น HOSxP ที่มีโรงพยาบาลจริงยืนยันว่ารันได้และผลถูกต้อง ถ้ายังไม่มีใครยืนยัน ให้เขียนว่า "ยังไม่มีการยืนยันจากโรงพยาบาลจริง (รอ community ช่วยทดสอบ)" ห้ามเดาว่าใช้ได้กับรุ่นไหน เมื่อมีคนยืนยันแล้วให้เปลี่ยนเป็นรุ่นที่ทดสอบจริง เช่น "HOSxP v3 (รพ.ชุมชนแห่งหนึ่ง, 2026-08)" |
| สถานะ | `draft` หรือ `validated` เท่านั้น (ดูคำอธิบายด้านล่าง) |
| ผู้เขียน | ชื่อผู้เขียนหรือ "MOPH KPI SQL Community" ถ้าไม่ต้องการระบุตัวตน |
| อัปเดตล่าสุด | วันที่แก้ไขไฟล์ล่าสุด รูปแบบ YYYY-MM-DD |
| นิยามอ้างอิง | สรุปนิยามสั้น 1-2 บรรทัด และชี้ไปที่ README ในโฟลเดอร์เดียวกันสำหรับรายละเอียดเต็ม |
| สิ่งที่ต้องปรับตามโรงพยาบาล | list ทุกจุดที่ผู้ใช้ต้องแก้ก่อนรัน เช่น รหัส lab, รหัสแผนก |
| ข้อจำกัด | list สั้นของสิ่งที่ query นี้ยังทำไม่ได้หรือกรณีที่นับไม่ครบ |

### สถานะ draft และ validated

- `draft` : query ใหม่ทุกตัวเริ่มที่สถานะนี้ รันได้ในโรงพยาบาลของผู้เขียนแต่ยังไม่มีใครอื่นยืนยัน
- `validated` : เปลี่ยนได้เมื่อมีโรงพยาบาลอื่นอย่างน้อย 1 แห่งรัน query แล้วยืนยันว่าผลสอดคล้องกับข้อมูลจริงของโรงพยาบาลนั้น (แจ้งผลผ่าน issue ของ repo)

## 3. รูปแบบ SQL

- SQL keywords ใช้ตัวพิมพ์ใหญ่ทั้งหมด: `SELECT`, `FROM`, `LEFT JOIN`, `GROUP BY`
- ตั้ง alias สั้นและสื่อความ เช่น `p` สำหรับ patient, `o` สำหรับ ovst, `lh` สำหรับ labs_head
- ใส่ comment ภาษาไทยในจุดสำคัญ: เงื่อนไขการนับ, เหตุผลของการ join, จุดที่นิยามกำกวม
- พารามิเตอร์ทั้งหมดอยู่บนสุดของไฟล์ด้วย `SET @var` เช่น:

```sql
SET @start_date := '2025-10-01';  -- เริ่มปีงบประมาณ 2569 (1 ต.ค. 2568)
SET @end_date   := '2026-09-30';  -- สิ้นปีงบประมาณ 2569 (30 ก.ย. 2569)
```

- ห้ามใช้ CTE (`WITH ... AS`) และห้ามใช้ window functions (`ROW_NUMBER() OVER ...`)
  เพราะหลายโรงพยาบาลยังใช้ MySQL 5.x เก่า ให้ใช้ derived table (subquery ใน FROM) แทน
- ทุกค่าที่ต่างกันตามโรงพยาบาลต้องมี comment `-- [ปรับตามโรงพยาบาล]` พร้อมคำอธิบายว่าปรับอย่างไร เช่น:

```sql
SET @hb_lab_code := '0000';  -- [ปรับตามโรงพยาบาล] รหัส lab_items_code ของ Hb
                             -- หาได้จาก: SELECT lab_items_code, lab_items_name
                             -- FROM lab_items WHERE lab_items_name LIKE '%Hb%';
```

- ตารางหรือคอลัมน์ที่ไม่อยู่ใน core list ของ [docs/hosxp-basics.md](hosxp-basics.md)
  ต้องมี comment กำกับว่าเป็น version-dependent และให้ผู้ใช้ตรวจด้วย `DESCRIBE` ก่อนรัน
- ผล lab (`lab_order.lab_order_result`) เป็น VARCHAR ต้องกรองด้วย
  `REGEXP '^[0-9]+([.][0-9]+)?$'` ก่อน `CAST(... AS DECIMAL(5,2))` เสมอ
  (เขียนจุดเป็น `[.]` ห้ามเขียน `\.` เพราะ MySQL ตัด backslash ใน string ทำให้จุด match ทุกตัวอักษร)
- รหัส ICD-10 ใน HOSxP ส่วนใหญ่เก็บแบบไม่มีจุด (O801 ไม่ใช่ O80.1) แต่บางแห่งต่างไป
  ให้ match แบบทนทาน เช่น `REPLACE(icd10, '.', '') LIKE 'O60%'`
- การวินิจฉัยหลัก (principal diagnosis) คือ `diagtype = '1'`

## 4. ผลลัพธ์ของ query

query แต่ละไฟล์ควรมี 2 ส่วน:

1. **Query สรุป (query หลัก)** : จบด้วยตารางสรุปที่มีอย่างน้อย 3 คอลัมน์
   ตัวตั้ง (numerator), ตัวหาร (denominator), ร้อยละ
   เพื่อให้เทียบกับตัวเลขในระบบ HDC ได้ทันที
2. **Query รายละเอียดรายบุคคล** : แยกเป็น statement ต่างหากในไฟล์เดียวกัน
   ใช้ไล่ตรวจรายคนว่าใครถูกนับหรือหลุดจากตัวตั้ง/ตัวหาร

คำเตือนที่ต้องใส่ไว้เหนือ query รายบุคคลทุกครั้ง:
ผลรายบุคคลมีข้อมูลส่วนบุคคลของผู้ป่วย ใช้ตรวจสอบภายในโรงพยาบาลเท่านั้น
ห้ามแชร์ออกนอกโรงพยาบาลในทุกช่องทาง (ดู [docs/data-privacy.md](data-privacy.md))

## 5. นิยามต้องมีแหล่งอ้างอิงจริง

- นิยามตัวตั้ง ตัวหาร และเงื่อนไขการนับ ต้องอ้างอิงจาก template ตัวชี้วัดของปีงบประมาณปัจจุบันใน HDC (https://hdcservice.moph.go.th) หรือ Health KPI กระทรวงสาธารณสุข (https://healthkpi.moph.go.th) หรือเอกสารวิชาการจริงที่ระบุชื่อได้ เช่น เกณฑ์ของ WHO
- ห้ามเขียนนิยามจากความจำ และห้ามอ้างเอกสารหรือ URL ที่ไม่ได้เปิดตรวจจริง
- ห้ามระบุค่าเป้าหมายหรือรหัสตัวชี้วัดทางการใน query หรือ README
  ให้เขียนว่า "ตรวจสอบนิยามและค่าเป้าหมายจาก template ตัวชี้วัดของปีงบประมาณปัจจุบันใน HDC หรือ Health KPI" แทน เพราะค่าเหล่านี้เปลี่ยนทุกปีและเอกสารในชุมชนจะล้าสมัย

## 6. ตัวอย่างผลลัพธ์ใน README

- README ของแต่ละ query ควรมีตารางตัวอย่างผลลัพธ์ เพื่อให้ผู้ใช้รู้ว่ารันแล้วหน้าตาเป็นอย่างไร
- ตัวอย่างต้องเป็นข้อมูลสมมติเสมอ และเขียนกำกับว่า "ข้อมูลสมมติ" ชัดเจน
- HN ในตัวอย่างใช้เลขที่เห็นชัดว่าปลอม เช่น 000001, 000002
- ห้ามนำผลรันจริงจากฐานข้อมูลโรงพยาบาล แม้จะตัดชื่อออกแล้ว มาใส่ในเอกสารสาธารณะ

ตัวอย่าง (ข้อมูลสมมติ):

| ตัวตั้ง | ตัวหาร | ร้อยละ |
|---|---|---|
| 12 | 80 | 15.00 |
