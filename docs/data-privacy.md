# นโยบายข้อมูลส่วนบุคคลและความปลอดภัยของข้อมูลผู้ป่วย

เอกสารนี้เป็นเอกสารที่สำคัญที่สุดใน repository นี้ ผู้ที่จะส่ง PR, เปิด issue หรือ comment ต้องอ่านก่อนทุกครั้ง

## หลักการ

Repository นี้เก็บ "โค้ด" เท่านั้น ห้ามมี "ข้อมูล" ผู้ป่วยโดยเด็ดขาด

หลักการนี้ครอบคลุมทุกพื้นที่ของ repository:

- ตัว query (.sql)
- ตัวอย่างผลลัพธ์ใน README
- issue และ comment
- Pull Request และ description
- screenshot ทุกชนิด

Query ทุกตัวในชุมชนนี้ออกแบบมาให้รันภายในโรงพยาบาลของแต่ละหน่วยบริการเอง ผลลัพธ์ที่ได้ไม่ต้องส่งกลับมาที่ชุมชน สิ่งที่ชุมชนต้องการคือ feedback เชิงโค้ด เช่น query รันไม่ผ่าน เงื่อนไขนับผิด หรือชื่อ column ไม่ตรงกับรุ่น HOSxP ที่ใช้

## สิ่งที่ห้ามโพสต์

ห้ามโพสต์สิ่งต่อไปนี้ไม่ว่ากรณีใด:

| ประเภท | ตัวอย่าง |
|---|---|
| เลขประจำตัวผู้ป่วย | HN, AN, VN จริงจากฐานข้อมูล |
| เลขบัตรประชาชน | CID ทั้งแบบเต็มและแบบปิดบางหลัก |
| ชื่อ-นามสกุล | ทั้งชื่อจริงและชื่อที่พอระบุตัวได้ |
| วันเกิด | birthday จากตาราง patient |
| ที่อยู่ | บ้านเลขที่, หมู่บ้าน, ตำบล ที่ผูกกับตัวบุคคล |
| ภาพหน้าจอที่มีข้อมูลจริง | screenshot จาก HOSxP, phpMyAdmin, HeidiSQL, Navicat ที่เห็นข้อมูลผู้ป่วย |
| ไฟล์ export จากฐานข้อมูลจริง | .xlsx, .csv, .sql dump ที่มีข้อมูลรายบุคคล |

ข้อมูลที่ "ปิดบางส่วน" เช่น CID ที่เห็น 6 หลักแรก ก็ยังถือว่าห้าม เพราะรวมกับข้อมูลอื่นแล้วอาจระบุตัวบุคคลได้

## แนวปฏิบัติ

### ตัวอย่างผลลัพธ์

ใช้ข้อมูลสมมติเสมอ และเขียนกำกับว่า "ข้อมูลสมมติ" ทุกครั้ง เช่น

ตัวอย่าง (ข้อมูลสมมติ):

| hn | ผลตรวจ | แปลผล |
|---|---|---|
| 000001 | 10.5 | ต่ำกว่าเกณฑ์ |
| 000002 | 12.1 | ปกติ |

HN สมมติให้ใช้รูปแบบที่เห็นชัดว่าไม่ใช่ของจริง เช่น 000001, 000002

### การรายงานปัญหา

เวลารายงานว่า query ให้ผลผิด ให้ใช้ตัวเลขรวม (aggregate) เท่านั้น เช่น

- ใช้ได้: "query นับได้ 152 ราย แต่รายงานใน HDC ได้ 148 ราย"
- ห้าม: แนบรายชื่อหรือ HN ของ 4 รายที่ต่างกัน

ถ้าจำเป็นต้อง debug รายเคส ให้ debug ภายในโรงพยาบาลของตัวเอง แล้วนำ "สาเหตุ" มาเล่า เช่น "เคสที่หายเป็นเคสที่ diagtype ไม่ใช่ 1" โดยไม่ต้องมีข้อมูลผู้ป่วยประกอบ

### Screenshot

ก่อนแนบ screenshot ทุกครั้ง:

1. ตรวจทุกมุมของภาพ รวมถึง title bar, tab, และแถบสถานะ ที่มักมีชื่อผู้ป่วยหรือ HN ค้างอยู่
2. ปิดทับ (redact) ข้อมูลส่วนบุคคลทั้งหมดด้วยการทาทึบ อย่าใช้การเบลอเพราะบางกรณีกู้กลับได้
3. ถ้าไม่แน่ใจ อย่าแนบ ใช้การพิมพ์ error message หรือโครงสร้างตารางแทน

## ความรับผิดชอบของผู้ใช้ query

- การรัน query กับฐานข้อมูลจริงเป็นความรับผิดชอบของแต่ละหน่วยบริการ ภายใต้ พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 และระเบียบของหน่วยงานของตนเอง
- ผลลัพธ์ที่ได้จาก query ในชุมชนนี้ใช้เพื่อตรวจสอบและเตรียมข้อมูลภายในโรงพยาบาลเท่านั้น ไม่ใช่ค่าทางการ ค่าทางการอ้างอิงจากระบบ HDC ของกระทรวง (https://hdcservice.moph.go.th)
- แนะนำให้สร้าง DB user แบบ read-only สำหรับงานตัวชี้วัดโดยเฉพาะ ไม่ใช้ user ที่มีสิทธิ์เขียน
- แนะนำให้รันบน replica หรือเครื่องสำรองข้อมูล และเลือกช่วงเวลานอกเวลาให้บริการ เพื่อไม่กระทบระบบ HIS หน้างาน ดูรายละเอียดเพิ่มที่ [hosxp-basics.md](hosxp-basics.md)
- ไฟล์ผลลัพธ์ที่ export ออกมา (.xlsx, .csv) ให้เก็บในเครื่องหรือ drive ของหน่วยงานตามระเบียบ ห้าม commit เข้า repository นี้ (.gitignore ของ repo กันไฟล์กลุ่มนี้ไว้แล้ว แต่อย่าพึ่ง .gitignore อย่างเดียว)

## หากพบข้อมูลผู้ป่วยใน repository

1. เปิด issue ทันที หรือติดต่อ maintainer โดยเร็วที่สุด
2. ใน issue ให้ระบุเพียงตำแหน่งของข้อมูล เช่น ชื่อไฟล์, หมายเลข PR, หมายเลข comment ห้าม copy ข้อมูลนั้นมาแสดงซ้ำใน issue
3. Maintainer จะลบทั้งไฟล์และประวัติ (git history) เพราะการลบไฟล์ด้วย commit ใหม่เฉย ๆ ไม่ได้ลบข้อมูลออกจากประวัติ ใครก็ยังเปิดดู commit เก่าได้
4. ผู้ที่โพสต์ข้อมูลควรตรวจสอบตามระเบียบของหน่วยงานตนเองด้วยว่าต้องรายงานเหตุการณ์หรือไม่
